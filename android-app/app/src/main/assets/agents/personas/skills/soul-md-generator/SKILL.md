# 角色创建技能（喵仓三件套）

在喵仓（meow-academy）中，一个完整角色由三个文件组成，存放于 `.agents/personas/<角色id>/`：

| 文件 | 用途 | 信息来源 |
|------|------|---------|
| `persona.yml` | 角色元数据：名字、简介、排序（前端展示用） | 访谈 → 角色名 + 一句话总结 |
| `SOUL.md` | 角色人格设定：身份、性格、语气、原则、边界 | 访谈 → 人格细节 |
| `USER.md` | 该角色专属的用户档案：主人偏好、沟通习惯 | 访谈 → 用户信息 |

通过 `personas/list` RPC 自动扫描目录，新建的角色立刻出现在聊天页角色选择器中。

## 工作流程

### 第 1 步：确定角色 id

角色 id = 文件夹名（小写中横线风格，如 `meow-teacher`、`sakura`、`code-partner`）。

先问用户：
- **角色名**：叫什么名字？它会显示在聊天页角色选择器的列表里
- **一句话简介**：如何用一句话描述这个角色？（这句会出现在角色卡片的副标题）

然后确定角色 id：建议用英文小写+中横线，如果用户没有偏好就自动从角色名生成（拼音→英文转写），确认后使用。

### 第 2 步：访谈收集

不要一次性抛出一堆问题。按下面顺序逐组提问，用户回答完一组再问下一组。如果用户一开始的描述已覆盖某个主题，直接跳过对应问题组。每组用自然的对话语气提问，每次只问 1-2 个问题，避免让用户感到被审问。

**角色背景**：这个角色有什么背景故事或经历？它是什么身份（助教 / 伙伴 / 客服 / 导师……）？

**人格特质**：最突出的 3-5 个性格特质是什么？每个特质要求一句具体描述，说明它如何体现在对话里（"直接→看到废话直接打断，给结论"）。

**语气**：说话倾向正式、随意、幽默还是直率？偏好简短结论还是详细讲解？在出错 / 紧急 / 用户沮丧的场景下语气应该怎样？

**原则**：有哪些必须遵守的原则（如"优先保证准确，宁可明确说不确定"）？有哪些绝对不做的事？

**沟通风格**：怎么称呼用户？可以用 emoji 吗？回复用什么格式？

**专业领域**：精通哪些领域？每个领域的深度如何？

**边界**：有哪些不该触碰的话题或行为？

**用户信息**（这部分填 USER.md）：主人怎么称呼？语言、沟通偏好（中文/英文、正式/随意）、工作时段？

### 第 3 步：生成三件套

#### 3.1 persona.yml

```yaml
name: <角色名>
description: <一句话简介>
```

#### 3.2 SOUL.md

使用下面的通用分节式模板，把访谈内容填进去。用词必须是访谈中用户实际说过或明确认可的表述，不要凭空美化。标题行（`# SOUL.md — ...`）之后**直接开始 `## Identity`**，中间不加任何说明性注释。

```markdown
# SOUL.md — [角色名]

## Identity
[角色定位与背景，2-3 句具体描述]

## Personality
- [具体特质：描述它如何体现在对话里]
- [具体特质]

## Tone
- [语气倾向]且[语气倾向]
- [语言风格偏好]
- [回复长度偏好]
- [特殊场景的语气]

## Principles
- 永远[原则]
- 绝不[原则]
- 优先[价值观]

## Communication Style
- 称呼用户为[形式]
- [emoji 使用偏好]
- [格式化偏好]

## Expertise
- [领域]：[深度与使用方式]
- [领域]

## Boundaries
- 不做[边界]
- 避免[边界]
```

#### 3.3 USER.md

```markdown
# USER.md — [用户/主人档案]

## 基本信息
- 称呼：[主人怎么叫你]
- 语言偏好：[中文/英文/双语]
- 沟通风格：[正式/随意/简洁/详细]

## 偏好
- 工作时段：[用户活跃时段]
- 情绪支持：[偏好的安慰方式]
- 格式偏好：[Markdown/纯文本/要点]
```

### 第 4 步：质量检查

交付前逐条对照，不满足就修改：

- [ ] **具体性**：每个特质都写到"如何体现"——能否预测 Agent 对未见话题的立场？
- [ ] **篇幅**：SOUL.md 不超过 100 行，50 行左右最佳，核心放前面
- [ ] **边界**：SOUL.md Boundaries 至少 2 条禁令
- [ ] **不越界**：不含项目指令、临时风格、API Key 或密码
- [ ] **无元注释**：标题行下直接是 `## Identity`，没有说明性注释
- [ ] **角色 id 有效**：文件夹名 = 角色 id，小写+中横线，在 `personas/` 下不重复
- [ ] **USER.md 不空泛**：至少包含称呼、语言、沟通风格三项

### 第 5 步：写入文件

将三件套写入 `.agents/personas/<角色id>/`：

1. 用 `Write` 工具依次写入 `persona.yml`、`SOUL.md`、`USER.md`（Write 自动创建目录）
2. 交付后告知用户：新建的角色**立刻**出现在聊天页角色选择器中（`personas/list` 自动扫描），可在右侧看板「工作设置」→「角色设定」切换使用

> 参考示例见 `references/examples/catgirl-companion-example.md`（完整的"喵娘陪伴"角色三件套质量标杆）。需要把握"具体到什么粒度"时先读它再动手。
