## 一、导航结构

### 1.1 底部导航（多板块 + 默认首页可设）

底部 Tab 包含：

| Tab | 内容 | 说明 |
|---|---|---|
| 💬 聊天 | 与 Pi Agent 对话（流式 + Markdown 渲染 + 引用来源） | 学习问答主入口 |
| 📁 文件管理 | **主要的数据中心**，默认进入知识库的文件 | 见第二节 |
| ⚙️ 我的/设置 | 设置、终端入口、模型管理、主题 | 见第四节 |

**默认首页设置功能**：用户可在设置里选择「打开 App 默认进入哪个板块」（聊天 / 文件管理 / 我的），App 记住该选择。

### 1.2 页面层级

```
┌─────────────────────────────┐
│  底部导航                   │
│  [💬聊天] [📁文件管理] [⚙️我的]│
└─────────────────────────────┘
  ├─ 聊天页 → 会话列表 → 会话详情（流式回复）
  ├─ 文件管理 → 知识库文件 / 全部文件 / 搜索 → 文件详情（Markdown 渲染+编辑）
  └─ 我的 → 设置 / 模型管理 / 终端（模拟终端）
```

## 二、文件管理（数据中心）

> 定位：主要的数据中心。默认进入 = 知识库的文件。

- 默认展示**知识库文件**（md 为主）
- 支持切换视图：知识库文件 / 全部文件
- 文件操作：打开（Markdown 渲染）、编辑、删除、重新索引

### 2.2 搜索（三种方式并存）

| 搜索方式 | 说明 |
|---|---|
| ① 传统文件名搜索 | 按文件名精确/模糊匹配 |
| ② 近似匹配搜索 | 模糊/容错匹配（如 fzy 风格），容忍拼写差异 |

- 文件管理页内有「终端」按钮 → 打开终端，**默认 cd 到知识库目录**（方便就地操作知识文件）
- 具体交互细节：之后再定

## 五、终端页（两个入口，两种语境）

| 入口 | 打开方式 | 默认路径 | 用途 |
|---|---|---|---|
| 设置 → 终端 | 从设置进入 | **模拟终端默认 home 路径** | 通用 shell 操作 |
| 文件管理 → 终端按钮 | 从文件管理进入 | **知识库目录** | 就地操作知识文件 |

- 终端页放设置里，但**不一定要从设置打开**（文件管理也有入口）
- 展示 Pi 进程 stdin/stdout 实时流、启动日志、命令交互

### 5.1 终端体验目标（主人 2026-08-11 反馈 ⭐）

> 主人要求：终端要**像 termux 一样**——可以自由切换文件目录、执行代码，像真的在用一个终端。

**当前（M2）实现**：RPC `bash` 命令，每条命令独立 shell。
**局限（已实测确认）**：
- pi 的 `session.cwd` 只在 session 构造时固定，RPC 协议**没有 set_cwd 命令**，bash 命令不接受 cwd 参数
- 所以 `cd` 不跨命令持久化（每条 bash 都是新 shell）
- 无真 PTY，交互式程序（vim/top 等）不可用

**修复方向（M2 补丁 → 远期）**：
1. **M2 补丁（立即）**：App 端维护**虚拟 cwd**——解析 `cd` 命令更新状态，其余命令前缀 `cd <虚拟cwd> &&` 再执行；双入口初始化不同 cwd（文件管理=知识库目录，设置=home）
2. **远期（真终端）**：在 runtime 里起持久 bash 进程（PTY），App 直连其 stdin/stdout——像 termux 一样的完整终端体验（待规划）
