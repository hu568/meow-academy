## 五、终端页（两个入口，两种语境）

| 入口 | 打开方式 | 默认路径 | 用途 |
|---|---|---|---|
| 设置 → 终端 | 从设置进入 | **模拟终端默认 home 路径** | 通用 shell 操作 |
| 文件管理 → 终端按钮 | 从文件管理进入 | **知识库目录** | 就地操作知识文件 |

- 终端页放设置里，但**不一定要从设置打开**（文件管理也有入口）
- 展示 Pi 进程 stdin/stdout 实时流、启动日志、命令交互

### 5.1 终端体验目标（主人 2026-08-11 反馈 ⭐）

> 主人要求：终端要**像 termux 一样**——可以自由切换文件目录、执行代码，像真的在用一个终端。

**当前（M2）实现**：RPC `bash` 命令，每条命令独立 shell。
**局限（已实测确认）**：
- pi 的 `session.cwd` 只在 session 构造时固定，RPC 协议**没有 set_cwd 命令**，bash 命令不接受 cwd 参数
- 所以 `cd` 不跨命令持久化（每条 bash 都是新 shell）
- 无真 PTY，交互式程序（vim/top 等）不可用

**修复方向（M3 真终端 ⭐）**：
1. **M2 补丁（已做）**：App 端虚拟 cwd——解析 `cd` 更新状态，其余命令前缀 `cd <虚拟cwd> &&`；双入口初始化不同 cwd ✅（2026-08-11）
2. **M3 真终端（termux 化）**：在 runtime 里起**持久 bash 进程（PTY）**，App 直连其 stdin/stdout——像 termux 一样自由切目录、执行代码、跑交互程序（vim/top）。终端不再是「逐条命令」而是「持续会话」。
   - 技术方向：`libc` PTY（`/dev/ptmx`）+ 转义序列渲染，或复用终端组件库（termux-terminal-view）
   - 与 Pi 进程关系：终端独立于 pi RPC 的 bash，Pi 仍走 RPC（聊天用）；终端页直连 bash PTY
   - 双入口语境保留：设置=home；文件管理=当前浏览目录（M3 起）
